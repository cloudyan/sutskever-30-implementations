## Day 61: 参数记忆（预训练知识）

**一句话**：模型知识被编码在神经网络权重中，通过反向传播调整存储。

**前置知识**：Day 1-2（向量与矩阵）、Day 11-13（导数与反向传播）、Day 31（MLE）

### 核心定义

- **参数记忆**：知识存储在 transformer 层的权重矩阵中
- **存储方式**：不是显式数据库，而是统计模式关联
- **形成过程**：数十亿次反向传播，调整权重矩阵
- **局限性**：静态（截止训练日期）、可能产生幻觉

### 核心机制

<div class="formula-box">

```
预训练流程：
输入文本 → Embedding → Transformer 层 → 预测下一个词
                    ↓
              计算损失 L = -log P(正确词)
                    ↓
              反向传播：∂L/∂W
                    ↓
              更新权重：W = W - η∂L/∂W
```

</div>

### 知识存储原理

| 知识类型 | 存储位置 | 示例 |
|---------|---------|------|
| 事实知识 | FFN 层权重 | "北京是中国首都" |
| 语言模式 | Attention 层 | 主谓宾结构 |
| 推理能力 | 多层组合 | 数学计算、逻辑推理 |
| 语义关联 | Embedding 空间 | "猫"与"狗"向量接近 |

### 几何直观

- **Embedding 空间**：语义相近的词向量距离近
- **注意力头**：不同头关注不同关系（语法、语义、共现）
- **FFN 层**：存储事实性知识的"记忆单元"

### AI 中的应用

- **知识编辑**：直接修改特定权重注入知识
- **模型融合**：合并多个模型的权重
- **持续学习**：在不遗忘旧知识的情况下学习新知识

### 关键公式

<div class="formula-box">

```
知识存储：
词向量：v_word ∈ R^d
注意力：Attention(Q,K,V) = softmax(QKᵀ/√d)V
FFN：FFN(x) = max(0, xW₁ + b₁)W₂ + b₂

知识编辑：
W_new = W_old + ΔW (直接修改特定权重)
```

</div>

## Day 62: 上下文记忆（In-Context Learning）

**一句话**：模型通过提示词中的上下文临时"记住"信息，无需更新权重。

**前置知识**：Day 56（注意力机制）、Day 29（联合分布）

### 核心定义

- **上下文记忆**：通过 Prompt 中的上下文临时学习
- **特点**：无需微调、即时生效、受限于上下文窗口
- **窗口长度**：通常 4K-128K tokens
- **机制**：Attention 让模型"看到"所有上下文信息

### 核心机制

<div class="formula-box">

```
In-Context Learning 流程：
Prompt: "猫 → cat, 狗 → dog, 房子 → house, 车 → ?"
        ↓
每个 token 计算 Attention：
Query: "车"的 Query 向量
Key: 所有上下文的 Key 向量
Value: 所有上下文的 Value 向量
        ↓
Attention 分数 = softmax(Q·K/√d)
        ↓
聚合 Value：输出 = Σ(Attention 分数 × Value)
        ↓
预测："车" → "car"
```

</div>

### 三种 In-Context 模式

| 模式 | Prompt 示例 | 效果 |
|------|-----------|------|
| Zero-shot | "翻译成英文：车" | 依赖预训练知识 |
| One-shot | "猫→cat。车→？" | 临时学习模式 |
| Few-shot | "猫→cat, 狗→dog, 房子→house。车→？" | 强化模式学习 |

### 几何直观

- **上下文窗口**：一个滑动窗口，包含所有可见信息
- **注意力权重**：每个位置对其他位置的关注程度
- **信息流动**：高权重位置的信息流向当前位置

### AI 中的应用

- **任务指令**：在 Prompt 中说明任务要求
- **示例学习**：提供少量示例让模型学会模式
- **角色扮演**：设定模型角色（"作为专家..."）

### 关键公式

<div class="formula-box">

```
上下文注意力：
对于位置 i，计算对所有位置 j 的注意力：
Attention(i) = Σⱼ softmax(Qᵢ·Kⱼ/√d) × Vⱼ

上下文窗口限制：
最大长度 L，只能看到位置 1 到 L 的信息
```

</div>

## Day 63: Q-K-V 机制详解

**一句话**：Q-K-V 通过相关性筛选，让模型"点亮"相关知识区域。

**前置知识**：Day 56（注意力机制）、Day 1（向量点积）

### 核心定义

- **Query (Q)**：我要找什么信息？
- **Key (K)**：我有什么信息？
- **Value (V)**：信息的具体内容是什么？
- **注意力分数**：Q·K（点积），度量相关性

### 核心机制

<div class="formula-box">

```
Q-K-V 计算流程：
1. 每个词编码为三个向量：Q, K, V
2. 计算注意力分数：Score = Q·Kᵀ/√d
3. Softmax 归一化：Attention = softmax(Score)
4. 聚合 Value：Output = Attention × V
```

</div>

### 为什么能"点亮"知识

**示例**：Prompt = "作为中国首都，北京..."

<div class="formula-box">

```
"首都"的 Query 向量：
- 与"北京"的 Key 点积 → 分数很高 ✓ (激活)
- 与"政治职能"的 Key 点积 → 分数较高 ✓ (激活)
- 与"烤鸭"的 Key 点积 → 分数很低 ✗ (抑制)

结果：
"首都"主要聚合了"北京"、"政治"等信息
忽略了不相关的"烤鸭"、"旅游"等信息
```

</div>

### Softmax 放大效应

<div class="formula-box">

```
原始分数：[8, 7, 2, 1]
Softmax 后：[0.46, 0.34, 0.12, 0.08]
→ 前两项占 80%

原始分数：[20, 2, 1, 1]
Softmax 后：[0.999, 0.0004, ...]
→ 第一项占 99.9%（极端聚焦）
```

</div>

### 几何直观

- **高维空间**：每个词是一个向量
- **点积**：度量两个向量的"对齐程度"
- **Softmax**：将分数转换为概率分布，放大差异

### AI 中的应用

- **Prompt 设计**：选择能激活正确知识的关键词
- **注意力可视化**：分析模型关注哪些位置
- **模型解释**：理解模型为什么生成某个词

### 关键公式

<div class="formula-box">

```
注意力分数：
Score(Q,K) = Q·Kᵀ/√d

Softmax 放大：
Attentionᵢ = exp(Scoreᵢ) / Σⱼ exp(Scoreⱼ)

信息聚合：
Output = Σᵢ Attentionᵢ × Vᵢ
```

</div>

### 思考题

为什么除以√d？不除会有什么问题？

## Day 64: Prompt 工程原理

**一句话**：Prompt 通过注意力机制引导模型在概率模式中找到正确路径。

**前置知识**：Day 63（Q-K-V 机制）、Day 42（熵）、Day 18（凸优化）

### 核心定义

- **Prompt 工程**：设计最优 Prompt 引导模型输出
- **本质**：不增加知识，但决定如何调用已有知识
- **作用机制**：激活正确区域、设定概率偏向、引导输出格式

### 三种影响机制

| 机制 | 说明 | 示例 |
|------|------|------|
| **激活知识区域** | 通过注意力"点亮"相关区域 | "政治职能"→激活政治相关知识 |
| **设定概率偏向** | 改变后续 token 的概率分布 | "深思熟虑"→更长推理链 |
| **引导输出格式** | 指定回答的结构和形式 | "列举 3 点"→结构化输出 |

### 核心机制

<div class="formula-box">

```
Prompt 影响流程：
差 Prompt: "说一下北京"
→ 激活所有"北京"相关信息（混杂）
→ 概率分布分散
→ 输出模糊

好 Prompt: "作为中国首都，北京的政治职能有哪些？"
→ 精准激活"首都职能"相关知识
→ 概率分布集中
→ 输出精准
```

</div>

### Prompt 优劣对比

| Prompt 类型 | 效果 | 注意力机制 |
|------------|------|-----------|
| 模糊 Prompt | 激活混杂信息 | 散射手电筒 |
| 精准 Prompt | 激活特定知识 | 聚焦手电筒 |
| 结构化 Prompt | 激活模式匹配 | 格式化输出 |
| 示例 Prompt | 激活类比推理 | Few-shot 学习 |

### 几何直观

- **概率云**：模型所有可能的输出构成一片云
- **差 Prompt**：在云中随机漫步
- **好 Prompt**：划定一条清晰路径

### AI 中的应用

- **任务指令**：清晰说明任务要求
- **角色扮演**：设定专家角色
- **思维链**：要求"逐步推理"
- **格式约束**：指定输出格式

### 关键公式

<div class="formula-box">

```
Prompt 优化目标：
max P(正确输出 | Prompt, 模型参数)

思维链 Prompt：
"请逐步推理：1)... 2)... 3)..."
→ 激活推理链模式
→ 减少跳步错误
```

</div>

### 思考题

## Day 65: RAG 原理（检索增强生成）

**一句话**：通过向量检索注入外部知识，让模型"记住"训练后产生的信息。

**前置知识**：Day 1（向量相似度）、Day 9（PCA 降维）、Day 56（注意力）

### 核心定义

- **RAG**：Retrieval-Augmented Generation
- **核心思想**：先检索相关知识，再注入 Prompt 让模型生成
- **优势**：无需微调即可使用最新知识、私有知识库

### 核心机制

<div class="formula-box">

```
RAG 流程：
1. 用户问题 → Embedding → 问题向量 q
2. 向量检索：在数据库中找最相似的文档
   相似度 = q·d / (||q|| × ||d||)
3. 取 Top-K 相关文档片段
4. 注入 Prompt：
   "根据以下文档回答问题：
   [文档片段 1]
   [文档片段 2]
   问题：{用户问题}"
5. LLM 生成回答
```

</div>

### 三种记忆对比

| 记忆类型 | 更新频率 | 知识来源 | 局限性 |
|---------|---------|---------|--------|
| 参数记忆 | 训练时 | 预训练数据 | 静态、截止训练日期 |
| 上下文记忆 | 推理时 | Prompt | 受限于窗口长度 |
| RAG | 按需 | 外部数据库 | 依赖检索质量 |

### 几何直观

- **向量空间**：问题和文档都映射为向量
- **相似度**：向量夹角越小越相关
- **检索**：在高维空间中找最近的邻居

### AI 中的应用

- **企业知识库**：内部文档、产品手册
- **最新信息**：新闻、股票、天气
- **专业领域**：医疗、法律、科研论文

### 关键公式

<div class="formula-box">

```
向量相似度（余弦）：
similarity = q·d / (||q|| × ||d||)

检索：
Top-K docs = argmax_d similarity(q, d)

RAG 生成：
P(answer | question) = Σ P(answer | question, docᵢ) × P(docᵢ | question)
```

</div>

### 思考题

## Day 66: 微调与 LoRA

**一句话**：通过梯度更新注入新知识，LoRA 用低秩适配器高效微调。

**前置知识**：Day 15（梯度下降）、Day 32（MAP）、Day 5（伪逆）

### 核心定义

- **全量微调**：用新数据继续训练，更新所有权重
- **LoRA**：Low-Rank Adaptation，只更新低秩适配器
- **优势**：参数高效、避免灾难性遗忘、可组合

### 核心机制

<div class="formula-box">

```
全量微调：
W_new = W_old - η∂L/∂W
→ 更新所有参数
→ 可能覆盖旧知识

LoRA：
W_new = W_old + ΔW
ΔW = BA (B∈R^(d×r), A∈R^(r×k), r<<d)
→ 只更新 A 和 B（低秩）
→ 保持 W_old 冻结
```

</div>

### 两种微调对比

| 方法 | 更新参数 | 灾难性遗忘 | 计算成本 | 可组合性 |
|------|---------|-----------|---------|---------|
| 全量微调 | 全部 | 严重 | 高 | 否 |
| LoRA | 低秩适配器 | 轻微 | 低 | 是 |

### 几何直观

- **权重空间**：全量微调在大空间中搜索
- **LoRA**：在低维子空间中搜索
- **低秩假设**：新知识可以用少量参数表示

### AI 中的应用

- **领域适配**：医疗、法律、金融等专业领域
- **个性化**：个人写作风格、对话风格
- **多任务**：不同 LoRA 适配器切换

### 关键公式

<div class="formula-box">

```
LoRA 更新：
h = Wx + BAx
W ∈ R^(d×k), B ∈ R^(d×r), A ∈ R^(r×k)
r << d (通常 r=8, 16, 32)

参数效率：
全量：d×k 个参数
LoRA：(d+r)×r ≈ d×r 个参数 (r<<d)
```

</div>

### 思考题

为什么 LoRA 能避免灾难性遗忘？从参数更新角度解释。

## Day 67: 灾难性遗忘

**一句话**：学习新知识时覆盖旧知识，是持续学习的核心挑战。

**前置知识**：Day 37（过拟合）、Day 66（微调）、Day 32（正则化）

### 核心定义

- **灾难性遗忘**：学习新知识后，旧知识性能大幅下降
- **原因**：新梯度更新覆盖了存储旧知识的权重
- **挑战**：稳定性（保留旧知识）vs 可塑性（学习新知识）

### 核心机制

<div class="formula-box">

```
遗忘过程：
1. 旧任务训练 → 权重 W_old 存储旧知识
2. 新任务训练 → 梯度更新 W_new = W_old - η∂L_new/∂W
3. 旧知识性能下降 → W_new 破坏了旧知识的权重模式
```

</div>

### 解决方案

| 方法 | 原理 | 效果 |
|------|------|------|
| **经验回放** | 混合新旧数据训练 | ⭐⭐⭐ |
| **弹性权重巩固** | 对重要权重施加惩罚 | ⭐⭐ |
| **LoRA** | 冻结原权重，只更新适配器 | ⭐⭐⭐ |
| **知识蒸馏** | 用旧模型指导新模型 | ⭐⭐ |

### 几何直观

- **权重空间**：旧知识占据某些区域
- **新训练**：将权重推向新区域
- **冲突**：新旧区域重叠部分被覆盖

### AI 中的应用

- **持续学习**：模型持续学习新知识
- **多任务学习**：同时学习多个任务
- **领域适应**：从通用到专业领域

### 关键公式

<div class="formula-box">

```
EWC (弹性权重巩固)：
L = L_new + λΣᵢ Fᵢ(Wᵢ - Wᵢ_old)²
Fᵢ：Fisher 信息矩阵，度量权重ᵢ对旧任务的重要性

知识蒸馏：
L = L_task + α·KL(P_old || P_new)
保持新旧模型输出一致
```

</div>

### 思考题

为什么混合新旧数据能缓解灾难性遗忘？

## Day 68: 少样本学习（Few-Shot Learning）

**一句话**：通过少量示例让模型学会任务模式，无需微调。

**前置知识**：Day 62（上下文记忆）、Day 63（Q-K-V 机制）

### 核心定义

- **Few-Shot**：提供少量示例让模型学会模式
- **机制**：In-Context Learning，通过注意力匹配示例模式
- **优势**：无需训练数据、即时生效、灵活

### 核心机制

<div class="formula-box">

```
Few-Shot Prompt：
示例 1: 猫 → cat
示例 2: 狗 → dog
示例 3: 房子 → house
问题：车 → ?

模型推理：
1. 计算"车"与示例的注意力
2. 匹配"中文→英文"的映射模式
3. 预测：车 → car
```

</div>

### 三种学习模式对比

| 模式 | 示例数 | 训练 | 效果 |
|------|--------|------|------|
| Zero-Shot | 0 | 否 | 依赖预训练 |
| One-Shot | 1 | 否 | 临时学习 |
| Few-Shot | 2-10 | 否 | 强化模式 |
| Fine-tuning | 100+ | 是 | 最佳 |

### 几何直观

- **示例空间**：每个示例是一个点
- **模式学习**：找到示例间的共同规律
- **泛化**：将规律应用到新问题

### AI 中的应用

- **快速原型**：快速测试新任务
- **低资源场景**：没有大量标注数据
- **多任务切换**：不同 Prompt 切换任务

### 关键公式

<div class="formula-box">

```
Few-Shot 注意力：
对于问题 q，计算对所有示例 eᵢ 的注意力
Attention(q) = Σᵢ softmax(q·eᵢ/√d) × answerᵢ

模式匹配：
找到示例中的共同模式 M
应用到新问题：answer = M(question)
```

</div>

### 思考题

为什么 Few-Shot 需要示例是高质量的？从模式匹配角度解释。

## Day 69: 链式思维（Chain-of-Thought）

**一句话**：要求模型"逐步推理"，激活推理链模式，减少跳步错误。

**前置知识**：Day 64（Prompt 工程）、Day 63（Q-K-V 机制）

### 核心定义

- **Chain-of-Thought (CoT)**：要求模型逐步展示推理过程
- **效果**：显著提升数学、逻辑推理任务准确率
- **机制**：激活推理链模式，强制中间步骤

### 核心机制

<div class="formula-box">

```
CoT Prompt：
"鸡兔同笼，头 35 个，脚 94 只。请逐步推理：
1. 设未知数
2. 列方程
3. 求解
4. 验证"

效果：
1. 激活"逐步推理"的注意力模式
2. 每个步骤作为下一步的上下文
3. 减少跳步错误
```

</div>

### 两种 Prompt 对比

| Prompt 类型 | 示例 | 准确率 |
|------------|------|--------|
| 直接回答 | "鸡兔同笼...各多少？" | 50% |
| CoT | "请逐步推理..." | 80%+ |

### 几何直观

- **推理链**：一条从问题到答案的路径
- **直接回答**：试图一步跳到终点（容易错）
- **CoT**：一步步走，每步都验证（更准确）

### AI 中的应用

- **数学问题**：代数、几何、微积分
- **逻辑推理**：演绎、归纳
- **代码生成**：逐步实现功能

### 关键公式

<div class="formula-box">

```
CoT 生成：
P(answer | question) = Πₜ P(stepₜ | question, step₁...stepₜ₋₁)

每个步骤都基于前面所有步骤
→ 减少累积误差
```

</div>

