## Windows Git Bash 安装 Claude Code CLI 核心要点

### 1. 安装方式选择

| 方式 | 命令 | 适用场景 |
|------|------|---------|
| **pnpm（推荐）** | `pnpm add -g @anthropic-ai/claude-code --allow-build=@anthropic-ai/claude-code --ignore-scripts=false` | 已用 pnpm 管理包 |
| npm | `npm install -g @anthropic-ai/claude-code` | 最简单，无权限问题 |
| npx | `npx @anthropic-ai/claude-code` | 临时使用，不全局安装 |

> **pnpm v10+ 关键变化**：默认阻止所有包的 build scripts，必须加以下参数：
> - `--allow-build=@anthropic-ai/claude-code`：授权原生包执行构建脚本
> - `--ignore-scripts=false`：确保不忽略脚本（默认可能是 true）

---

### 2. pnpm 安装常见问题

| 错误 | 原因 | 解决 |
|------|------|------|
| `Error: claude native binary not installed` | postinstall 脚本未执行 | 加 `--allow-build` 参数重装 |
| `ERR_PNPM_PUBLIC_HOIST_PATTERN_DIFF` | 全局目录配置冲突 | `rm -rf $(pnpm root -g)` 清理后重装 |
| `Ignored build scripts` | pnpm v10 安全机制 | `pnpm approve-builds -g` 或 `--allow-build` |
| `Unknown option: 'omit-optional'` | 参数名错误 | pnpm v10 用 `--config.xxx` 或直接省略 |

### 3. Git Bash 路径配置

Claude Code 在 Windows 上需要显式指定 Git Bash 位置：

```bash
# which bash
/usr/bin/bash
# 输出不是真的路径，通过以下命令获取真实路径

# 获取真实 Windows 路径
cygpath -w /usr/bin/bash
# 输出示例：C:\Users\xxx\AppData\Local\Programs\Git\usr\bin\bash.exe
```

**设置环境变量**：
```bash
# 临时（当前会话）
export CLAUDE_CODE_GIT_BASH_PATH="C:\Users\xxx\AppData\Local\Programs\Git\usr\bin\bash.exe"

# 永久（写入 ~/.bashrc）
echo 'export CLAUDE_CODE_GIT_BASH_PATH="C:\Users\xxx\AppData\Local\Programs\Git\usr\bin\bash.exe"' >> ~/.bashrc
```

### 5. 完整安装流程（pnpm 版）

```bash
# 0. 如果已安装过，先完全卸载（重要！）
pnpm remove -g @anthropic-ai/claude-code
# 或
npm uninstall -g @anthropic-ai/claude-code

# 清理可能的残留
rm -rf $(pnpm root -g)/@anthropic-ai
rm -rf ~/.cache/claude-code

# 1. 安装（必须加 --allow-build 和 --ignore-scripts=false）
pnpm add -g @anthropic-ai/claude-code --allow-build=@anthropic-ai/claude-code --ignore-scripts=false

# 2. 配置 Git Bash 路径
export CLAUDE_CODE_GIT_BASH_PATH="C:\Users\xxx\AppData\Local\Programs\Git\usr\bin\bash.exe"

# 3. 配置代理端点和 API Key（根据服务商文档）
export ANTHROPIC_API_KEY="your-proxy-api-key"

# 4. 验证安装
claude --version

# 5. 启动
claude
```

**⚠️ 重要提示**：
- 如果之前安装失败过，**必须先完全卸载**再重新安装
- 检查 `claude --version` 确认安装成功
- 出现 `claude: command not found` 检查 pnpm 全局目录是否在 PATH 中

### 6. 关键结论

- **pnpm v10+ 必须显式授权 build scripts**：`--allow-build=@anthropic-ai/claude-code --ignore-scripts=false`
- **已安装过的必须先卸载**：`pnpm remove -g` 并清理缓存，否则新参数不生效
- **Git Bash 需要手动指定 `bash.exe` 路径**：Claude Code 不会自动识别虚拟路径 `/usr/bin/bash`
- **国内使用必须配置代理端点**：直接连 `api.anthropic.com` 会 `ERR_BAD_REQUEST`
- **推荐用 npm 安装**：如果 pnpm 反复出问题，npm 没有 hoist/scripts 限制，更省心

# SSH "no matching host key type" 故障处理

## 问题现象

```bash
Unable to negotiate with 10.1.17.2 port xxxx: no matching host key type found. Their offer: ssh-rsa
fatal: Could not read from remote repository.
```

## 根本原因

- OpenSSH 8.8+ 版本默认禁用 `ssh-rsa` 算法（存在安全性问题）
- 老旧的 Git 服务器仍使用 `ssh-rsa` 作为 host key

## 解决方案

在 `~/.ssh/config` 中添加：

```ssh
Host coding.xxx.com
    HostName 10.1.17.2
    HostKeyAlgorithms +ssh-rsa
    PubkeyAcceptedAlgorithms +ssh-rsa
```

## 关键细节

| 配置项 | 说明 |
|--------|------|
| `Host` | 匹配 `git remote -v` 中的 **hostname**，不是 IP |
| `HostName` | 指定实际连接的 IP 地址 |
| `+ssh-rsa` | **追加**到默认列表（带 `+` 号），不是替换 |

## 排查命令

```bash
# 确认 remote URL 中的 hostname
git remote -v

# 查看详细握手过程，确认加载了哪个配置
ssh -v git@coding.xxx.com

# 测试连接
ssh -T git@coding.~~xxx~~.com
```

## 注意事项

1. SSH 配置中的 `Host` 必须匹配 git URL 中的 hostname
   - 错误：`Host 10.1.17.2`（git URL 是 `coding.xxx.com`）
   - 正确：`Host coding.xxx.com`

2. 如果服务器同时用于普通 SSH 登录，建议单独配置：
   ```ssh
   Host git-server
       HostName coding.xxx.com
       HostKeyAlgorithms +ssh-rsa
       PubkeyAcceptedAlgorithms +ssh-rsa
   ```

## 🤖 大模型与 Prompt 机制学习笔记

### 1. 自进化 Agent 实现方式

**核心机制**：

```python
class SelfEvolvingAgent:
    def run_with_evolution(self, task):
        # 执行
        result = self.execute(task)
        
        # 反射：分析成功/失败
        reflection = self.llm.generate(
            f"Task: {task}\nResult: {result}\n"
            "Analyze what went wrong and how to improve."
        )
        
        # 进化：更新提示词或策略
        self.system_prompt = self.evolve_prompt(reflection)
        
        return result
```

**四种自进化方式**：
1. **反射循环** - 执行→分析→改进
2. **技能库积累** - 像 Voyager 那样保存成功策略为可复用技能
3. **提示词进化** - APE/OPRO 让 LLM 生成并评分多个提示词变体
4. **元学习层** - 用"元 Agent"监控优化主 Agent 的系统提示词、工具选择、任务分解

### 2. 大模型如何记住知识

| 记忆类型 | 类比人类 | 技术实现 | 特点 |
|---------|---------|---------|------|
| **参数记忆** | 长期记忆 | 神经网络权重 | 静态、截止训练日期、可能幻觉 |
| **上下文记忆** | 短期记忆/注意力 | Attention 机制 | 无需微调、受限于上下文窗口 |
| **RAG** | 查资料 | 向量检索 | 注入外部知识库、最新文档 |
| **微调** | 重新学习 | 梯度更新/LoRA | 可能灾难性遗忘 |

**参数记忆的本质**：知识被编码在权重矩阵中，通过反向传播调整 transformer 层，存储的是词与词的统计关联模式（如"北京"与"中国首都"在向量空间中邻近）。

---

### 3. Prompt 优劣如何影响回答

**核心原因**：模型存储的是"概率关联模式"，而非确定性事实数据库。Prompt 引导模型在概率模式中找到正确路径。

**三种影响机制**：

1. **激活正确的知识区域**
   - 差 Prompt：激活混杂信息
   - 好 Prompt：精准激活相关知识路径

2. **设定概率分布偏向**
   - "深思熟虑"→更长推理链条、结构化输出
   - "快速回答"→简洁直接

3. **引导任务格式**
   - "列举 3 个要点"→结构化输出
   - "用类比解释"→比喻映射模式
   - "逐步推理"→链式思维（CoT）

**本质**：Prompt 不增加模型知识，但决定它能多准确地调用已有知识。

---

### 4. Prompt 通过注意力机制"点亮"知识区域的原理

**Q-K-V 机制**：
- **Query (Q)**: 我要找什么信息？
- **Key (K)**: 我有什么信息？
- **Value (V)**: 信息的具体内容是什么？

**注意力分数 = Q × K（点积）**
- 分数高 → 相关 → 信息传递多
- 分数低 → 不相关 → 被屏蔽

**Softmax 放大效应**：
```
原始分数：[8, 7, 2, 1]
Softmax 后：[0.46, 0.34, 0.12, 0.08]

原始分数：[20, 2, 1, 1]
Softmax 后：[0.999, 0.0004, ...] ← 极端聚焦
```

**形象类比**：
- 模型知识 = 一片黑暗的图书馆
- 差 Prompt = 手电筒散射，照亮一大片区域（杂乱）
- 优质 Prompt = 手电筒聚焦，精准照亮某一排书架

**一句话总结**：
> Prompt 通过提供高权重的 Query 向量，让注意力层计算出偏向特定知识区域的注意力分布，从而在庞大的参数空间中"照亮"正确的路径。
